Per D-02: The initial Alembic migration (9ccde6d944e6) is EMPTY — existing tables were created via `init_db()` calling `Base.metadata.create_all()`. This means:
- On a DB created by `init_db()`: all tables exist, `alembic upgrade head` with the new migration should use `IF NOT EXISTS` or `create_check_constraint` pattern.
- On a fresh DB: `alembic upgrade head` runs empty initial migration, then the new migration tries to FK-reference `users` table that doesn't exist → FAILS.

**Solution:** Generate the migration with `alembic revision --autogenerate -m "add agent_memories table"`, then edit it to use `op.create_table(...)` with `exist_ok=True`-equivalent pattern: check if the table exists before creating. Alternatively, the migration should be written manually with `op.create_table("agent_memories", ...)` using `sa.ForeignKeyConstraint` with `ondelete="CASCADE"`.

For test/dev environments, `init_db()` already calls `create_all()`, so the migration is mainly for production schema tracking. The executor should:
1. Generate migration: `alembic revision --autogenerate -m "add agent_memories table"`
2. Review and clean up the auto-generated migration
3. Add `import sqlalchemy as sa` and ensure the migration includes: table creation, foreign key to users.id, and composite index
4. Verify: run `alembic upgrade head` on a DB that already has tables (the normal dev flow)
