# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-04-16
**Phases:** 0-4 + E2E
**Total Plans:** 20

## Overview

Taste-based travel itinerary generator MVP for Chinese young travelers. Users input natural language travel preferences and receive personalized, narratively rich single-city itineraries generated via a 4-stage pipeline (intent extraction → POI filtering → LLM+SOUL generation → route validation) with real-time SSE streaming. Includes interactive adjustment with preview, blind test infrastructure, and Docker deployment.

## Milestone Summary

**Key Decisions:**
- Decision: Python + Vue tech stack (Rationale: Team familiarity, FastAPI async for SSE, Vue component model) — ✓ Good
- Decision: SQLite storage (Rationale: MVP data <1MB, all in memory) — ✓ Good
- Decision: Taste from data not model (Rationale: No fine-tuning, SOUL prompt + structured data controls output) — ✓ Good
- Decision: DeepSeek-V3 LLM (Rationale: ¥1/M token, 100K+ context) — ✓ Good
- Decision: SSE progress feedback (Rationale: 30-60s pipeline needs stage-by-stage progress) — ✓ Good
- Decision: Frontend no map embed (Rationale: Timeline-first, reduce API calls) — ⚠️ Revisit for v1.1
- Decision: bcrypt direct (not passlib) (Rationale: passlib 1.7.4 incompatible with bcrypt 4.x) — ✓ Good

**Issues Resolved:**
- Fixed SOUL template {{VAR}} → {VAR} format mismatch
- Fixed DB save race condition (moved save before "done" event)
- Fixed JWT secret key mismatch across auth modules
- Fixed SSE termination checking event_type not status
- Fixed cross-chunk SSE buffer for large adjust_preview events
- Fixed bcrypt 4.x / passlib incompatibility (replaced with direct bcrypt)
- Fixed nginx DNS resolution with lazy upstream
- Fixed preview mode not reading updated_itinerary.days

**Issues Deferred (Known Gaps):**
- Amap POI search not wired into pipeline (only fixed 97 POIs)

- Test runner broken (import paths + async engine misuse)

- No frontend auth UI despite complete backend auth
- No map visualization despite @amap/amap-jsapi-loader installed
- No Alembic migrations, no automated tests, no rate limiting
