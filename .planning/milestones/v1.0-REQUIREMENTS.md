## v1 Requirements — Outcome Summary

### Intent Extraction

- [x] **INTENT-01**: User can input natural language travel request — ✅ Implemented (HomeView textarea + generate endpoint)
- [x] **INTENT-02**: System extracts structured preferences — ✅ Partially implemented (city, days, budget_level, pace, rating_level, interests extracted; D1/D3/D7 not as separate dimensions)
- [x] **INTENT-03**: System rejects multi-city trips — ✅ Implemented (ValueError in parse_intent_output)
- [x] **INTENT-04**: System rejects trips >3 days — ✅ Implemented (ValueError in stage1_intent.py)

### Itinerary Generation

- [x] **GEN-01**: 4-stage pipeline — ✅ Implemented (intent → prefilter → generation → validation)
- [x] **GEN-02**: Each node contains required fields — ✅ Implemented (name, time_slot, highlight_note, vibe_description, walk_to_next_minutes, tier)
- [x] **GEN-03**: "Local friend" voice — ✅ Implemented (SOUL prompts soul_system.md + soul_user_template.md)
- [x] **GEN-04**: Max 4 nodes/day + buffer time — ⚠️ Max 4 enforced; explicit buffer time not modeled
- [x] **GEN-05**: SSE progress feedback — ✅ Implemented (StageProgress component + 4-stage events)
- [x] **GEN-06**: End-to-end latency ≤60s — ⚠️ Not measured; typically 30-60s depending on LLM response

### Data Acquisition

- [x] **DATA-01**: System fetches POI from Amap API — ✅ AmapService.search_pois implemented; used in acquisition script only (not live pipeline)
- [x] **DATA-02**: POI mapped to D1/D3/D7 — ⚠️ D1/D3/D7 not explicitly modeled; taste_tags + rating used instead
- [x] **DATA-03**: Auto-tiering — ✅ Implemented (rating >4.0 non-chain → Tier B)
- [x] **DATA-04**: Tier B LLM taste_tags — ✅ Implemented (acquire_shanghai_pois.py)
- [x] **DATA-05**: Full caching strategy — ⚠️ AmapCache model exists but caching disabled (no db_session)
- [x] **DATA-06**: Semi-automated acquisition script — ✅ Implemented (scripts/acquire_shanghai_pois.py)
